## Blocking item

1. **C1's "no third call" is false on the deployed config.** With `anchor_chain.failover: [z-ai/glm-5.3]` (reviewer profile config, line 242), a failed budget retry falls through to `_recover_empty_consult(skip_minimal=True)`, which still walks `_failover_endpoints` — measured 3 provider calls (2 primary + 1 glm). The unit's own test asserts `len(calls) == 2` only because its fixture returns `_anchor_chain_block -> {}` with no failover; it cannot see the live path. Worse, the failover call re-sends the ORIGINAL allowance (`max_tokens=23585`), so a budget-exhausted consult is likely to die there for the same reason — the third call is spend without a budget. Fix one of: (a) pass the raised allowance to the failover call, (b) set `skip_failover` when the budget retry fired, or (c) amend C1 to "at most one budget retry; the pre-existing failover arm still makes one call" and make the test state the failover explicitly.
